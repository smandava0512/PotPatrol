# PotPatrol API v1 — Developer 2 contract

Base URL: `http://127.0.0.1:8000` locally. JSON endpoints require `X-Device-Token: <device credential>`; the authenticated upload PUT requires the same header. Provision **one distinct random credential per device** through `POTPATROL_DEVICE_TOKENS` (comma-separated) and deliver it privately. A drive and its hazards/evidence are accessible only to the credential that created it, even if another device knows its UUID. Remove a credential from the list and restart the API to revoke it; that device's existing drives then become inaccessible until its original credential is restored. `POTPATROL_DEVICE_TOKEN` is supported for a single-device legacy demo but **must not be shared across devices**. IDs are UUIDs. Times are absolute UTC ISO 8601 (`Z`); offsets in integer milliseconds from the **first actual recorded video frame**, not app launch or upload time. Locations are WGS84 phone positions, not surveyed pothole coordinates. Unknown accuracy, speed, severity, and location are `null`.

| Call | Request | Success |
| --- | --- | --- |
| `POST /v1/drives` | `{}` | `201 {"drive_id": UUID, "status":"created"}` |
| `POST /v1/drives/{id}/upload-init` | `{}` | `200 {"upload_url": absolute authenticated local URL, "method":"PUT", "headers":{"Content-Type":"video/mp4"}, "expires_at": UTC time}` |
| `PUT /v1/drives/{id}/video` | MP4 body, `Content-Type: video/mp4`, device token | `204`; each successful upload replaces the drive's selected key with a new immutable object, but the previous object remains private |
| `POST /v1/drives/{id}/locations` | `{"samples":[{"offset_ms":0,"recorded_at":"2026-09-26T12:00:00Z","latitude":25.7617,"longitude":-80.1918,"horizontal_accuracy_m":5.0,"speed_mps":4.0}]}` | `200 {"accepted":1}`; identical repeated offset is idempotent, conflicting repeat is `409` |
| `POST /v1/drives/{id}/complete` | `{}` (legacy) or `{"video_started_at":"2026-09-26T18:04:12Z"}` (UTC of first successfully written video frame) | `200 {"drive_id":UUID,"status":"queued"}` (or current status if already queued/processing/complete); `409` if video absent or concurrent replacement won; retry completion on `409` |
| `POST /v1/drives/{id}/retry` | `{}` | `200 {"drive_id":UUID,"status":"queued"}` only after `failed` |
| `GET /v1/drives/{id}` | — | `200 {"drive_id":UUID,"status":enum,"stage":string/null,"error":string/null,"analysis_mode":"fixture"|"model"|"legacy"|null,"hazards":[...]}` |
| `DELETE /v1/drives/{id}` | — | `204` after deleting all uploaded/replaced MP4s and evidence under the drive's private storage prefixes, plus its GPS, jobs, hazards, evidence metadata and report drafts; `401` without a valid device token, `404` for missing/foreign/already-deleted drives, `503` on storage cleanup failure (retry the same DELETE) |
| `GET /v1/hazards/{id}/evidence` | — | private authenticated JPEG |
| `POST /v1/hazards/{id}/report-draft` | `{}` | persisted editable draft package (`report_id`, `fields`, `destination`, `submission_status`) |
| `GET /health` | — | `{"status":"ok"}` (no auth) |

Status enum: `created`, `uploading`, `queued`, `processing`, `complete`, `failed`. `GET` hazard: `hazard_id`, `category`, `confidence` [0,1], `severity` nullable, `severity_basis` nullable, `evidence_url` (authenticated API path), `video_offset_ms`, `observed_at` nullable UTC, `location` nullable (`latitude`, `longitude`, `horizontal_accuracy_m`, `source":"phone_interpolated"|"phone_sample"`), `review_state` (`needs_review`). Missing/low-quality GPS yields `location:null` without dropping the hazard. `analysis_mode:"fixture"` denotes deterministic demo data, not real inference; `"legacy"` means an older analyzer did not identify its mode. The optional `video_started_at` is accepted only at first completion and is never derived from GPS/upload time; `{}` leaves all `observed_at` values null. Reports use nested `destination: {"status":"needs_review"|"unsupported"|"verified"|"unverified", "url":string|null, "candidates":[], "reason":string, "sources":[]}`. With the Dev 3 adapter, missing GPS yields `needs_review`/empty candidates/null URL; outside supported area yields `unsupported`/null URL; Miami-Dade GPS alone yields `needs_review` with candidate agencies, but no verified URL until ownership is established. Without the adapter, the safe legacy default remains `unverified`/null URL. Report `fields.observation_time` holds `{ "value": UTC|null, "source": "device_clock"|"unassessed" }`. `submission_status` stays `not_submitted`; a portal handoff is not submission. Errors use HTTP status with `detail`.

Report `fields` preserve the flat iOS v1 contract: `category` and `description` are strings; `latitude` and `longitude` are numbers or null; `observation_time` retains its `{value, source}` shape. The Dev 3 adapter stores the original annotated fields under `fields.provenance`. Old server-cached drafts with wrapped fields are normalized on the next report-draft request, preserving their ID, destination and submission status. The phone must re-fetch instead of reusing its locally cached broken draft; preserve user edits and receipts when adding a refresh action. GPS alone still does not verify a destination, and candidate selection is a separate client workflow.

Limits: max MP4 size 100 MiB, max duration 10 minutes (if readable by ffprobe), max 2000 location samples per batch, offset <= 600000 ms. Raw video never has a public URL. Upload authorization expires 15 minutes after the latest upload-init; request another to renew. The returned URL is the same authenticated route on each renewal, so an older copy also works during the current authorization window. Replaced objects remain private until deletion of the drive (or operator retention cleanup). Completing with no GPS is allowed and yields location-unavailable hazards. For local development use SQLite by default; set `POTPATROL_DATABASE_URL` to a Postgres URL for local/hosted Postgres. No extensions required. `POTPATROL_DEVICE_TOKENS` (preferred, distinct per device), legacy single-device `POTPATROL_DEVICE_TOKEN`, `POTPATROL_STORAGE_DIR`, `POTPATROL_ANALYZER`, `POTPATROL_REPORTER`, and optional `POTPATROL_S3_BUCKET`/`POTPATROL_S3_PREFIX`/`POTPATROL_S3_ENDPOINT_URL` configure the service. Legacy `ROADWATCH_*` settings remain accepted as fallback for existing deployments; new names take precedence.

Worker handoff (Developer 3): Install `worker/` as `potpatrol-vision`, configure `POTPATROL_ANALYZER=potpatrol.integration:analyze` and `POTPATROL_REPORTER=potpatrol.integration:draft_report`. The adapter calls `potpatrol_vision.analyze(video_path, output_dir)`, validates its written `analysis.json` and local JPEGs, stores one hazard/evidence per event, and associates GPS/time if provided. `POTPATROL_ANALYSIS_MODE=fixture` selects the **two-event synthetic fixture** only for integration/demo; unset it for real model inference, which requires Dev 3's model dependencies and a real MP4. Fixture output must be labeled via `analysis_mode`. On invalid video/model failure the job fails, not an empty-hazard success. The report adapter calls `potpatrol_vision.report.draft_report(hazard, evidence_path, lat, lon, accuracy_m, observed_at)` and maps its flat destination fields into the canonical nested API; it does not establish ownership from GPS. See `docs/contracts/analysis.md` and `docs/contracts/examples/backend-additions.json`. The worker is a separate `python -m potpatrol.worker --once` / `--loop` process.
